# MuseClaw

> **企业常驻型多智能体数字员工工作站 (Enterprise Always-On Multi-Agent Workstation)**  
> 具备专属常驻沙箱、通讯录式多智能体协同、确定性安全哨兵风控与自动化执行能力的企业级 Agent 平台。

---

## 🎯 产品定位与核心特性

### 1. 核心定位
**“不仅是对话框，更是每个员工的专属 AI 虚拟团队。”**  
为每位企业员工分配专属、常驻、高安全隔离的执行沙箱，通过像通讯录一样自然的交互方式，调度不同专业角色的“数字员工”处理跨系统复杂工作流。

### 2. 核心代际差异
| 维度 | 传统对话 Agent | 单任务执行沙箱 | **MuseClaw (本系统)** |
| :--- | :--- | :--- | :--- |
| **交互形态** | 单一聊天输入框，被动问答 | 单一任务临时执行卡片 | **虚拟团队通讯录（Roster）+ 双端协同（Web + 企业 IM）** |
| **环境生命周期**| 无底层环境或无状态调用 | 按任务临时分配，跑完即销毁 | **员工专属常驻沙箱（Always-on），持久化登录态与工作区** |
| **安全管控** | 依靠 Prompt 提示词防越权 | 简单的命令正则黑白名单 | **确定性 Sentinel 哨兵内核（物理拦截不可逆高危操作）** |
| **主动性** | 零主动性（仅被动等待提问） | 零主动性 | **支持自主巡检、定时工单处理与主动消息推送** |
| **资产沉淀** | 仅沉淀文本对话 | 无数据资产留存 | **成功执行轨迹（Trajectory）自动沉淀为私有微调数据** |

## 🏛️ 系统总体架构

MuseClaw 采用分层解耦的分布式架构：

```
+-------------------------------------------------------------------------+
|                       1. 统一接入层 (Access Layer)                      |
|   +---------------------------------+   +---------------------------+   |
|   |  Web 门户 (通讯录 Roster 模式)   |   | 企业 IM (飞书/企微/钉钉)  |   |
|   |  - 多角色虚拟员工列表           |   | - 异步派单 / 进度推送     |   |
|   |  - 流式可视化卡片 & 投屏        |   | - 跨端高危动作一键审批    |   |
|   +---------------------------------+   +---------------------------+   |
+-------------------------------------------------------------------------+
                                    │
                                    ▼ (流式事件协议 & WebSocket)
+-------------------------------------------------------------------------+
|                  2. 中控与调度层 (Control & Relay Hub)                  |
|   +-----------------------------------------------------------------+   |
|   | 统一状态与会话中继 (Session Relay Engine)                       |   |
|   +-----------------------------------------------------------------+   |
|   +-----------------------------------------------------------------+   |
|   | Sentinel 确定性安全哨兵 (高危行为拦截 / 动态求证分发)           |   |
|   +-----------------------------------------------------------------+   |
|   +-----------------------------------------------------------------+   |
|   | 技能调度中心 (Skill Registry: 企业公共技能库 + 个人私有技能)     |   |
|   +-----------------------------------------------------------------+   |
+-------------------------------------------------------------------------+
                                    │
                                    ▼ (容器隔离与沙箱调度接口)
+-------------------------------------------------------------------------+
|              3. 执行与沙箱层 (Per-User Isolated Sandboxes)              |
|                                                                         |
|  [员工 A 专属沙箱]                       [员工 B 专属沙箱]              |
|  +-----------------------------------+  +----------------------------+  |
|  | 沙箱执行引擎 (Agent Runtime)       |  | 沙箱执行引擎               |  |
|  | 持久化 Chromium (保留内网登录态)   |  | 持久化 Chromium            |  |
|  | Linux 隔离 Shell / 自动化工具链   |  | Linux 隔离 Shell           |  |
|  | 个人持久化卷 (挂载 Skills/Workspace) | 个人持久化卷               |  |
|  +-----------------------------------+  +----------------------------+  |
+-------------------------------------------------------------------------+
                                    │
                                    ▼ (异步日志流)
+-------------------------------------------------------------------------+
|                 4. 数据飞轮与自进化层 (Data & Learning)                |
|  +-------------------------------------------------------------------+  |
|  | 任务执行轨迹收集器 (Trajectory Exporter -> 导出训练格式)          |  |
|  | 技能自提炼引擎 (Skill Miner: 成功链路反思 -> 自动封装参数化脚本)  |  |
|  +-------------------------------------------------------------------+  |
+-------------------------------------------------------------------------+
```

## 📂 项目模块结构

```
MuseClaw/
├── apps/
│   ├── web/                # 通讯录式 Web 工作台 (Roster UI)
│   ├── gateway/            # 统一会话中继与企业 IM 适配网关
│   └── sentinel/           # 确定性安全哨兵服务 (Security Interception Engine)
├── packages/
│   ├── protocol/           # 跨端事件标准库 (数据模型与事件定义)
│   ├── sandbox-core/       # 沙箱生命周期与执行核心封装
│   └── skills-registry/    # 全局技能与个人技能存储与版本管理
├── docs/                   # 详细架构与落地设计文档
└── README.md
```

> `apps/web` 是 React 19 + TypeScript + Vite 的单页应用（源码在 `src/`，产物在 `dist/`）。
> gateway 只托管 `dist/`，不再内置任何静态 HTML 页面。

## 🧑‍💻 本地运行

```bash
pnpm install

# 1. 构建前端（gateway 只读 dist，没有构建会返回 503 提示页）
pnpm --filter @museclaw/web build

# 2. 启动网关 + 工作台
pnpm dev            # http://localhost:8799

# 前端热更新（可选，API 由 Vite 代理到 8799）
pnpm dev:web        # http://localhost:5173
```

类型检查：`pnpm exec tsc -p apps/web/tsconfig.json --noEmit`

## 🚀 核心迭代路线 (Roadmap)

- [x] **Milestone 1: 协议与薄核状态机**
  - 核心事件规范确立（Task Plan, Approval Request, Stream Delta）。
  - 实现约 120 行极简 Agent Loop 状态机与 Sentinel 拦截切面。
- [x] **Milestone 2: 确定性安全门禁 (Sentinel)**
  - 拦截高危破坏性系统调用与操作。
  - 状态挂起与恢复流程完成（Pending -> Approval -> Resume）。
- [x] **Milestone 3: 企业 IM 通道与双端审批闭环**
  - **如流 (Infoflow)**：支持 Webhook 验签、AES-256 解密、私聊交互与文字审批闭环。
  - **飞书 (Feishu / Lark)**：支持开放平台 Challenge 校验、消息加解密、原生交互卡片（一键允许/拒绝按钮回写）、文本审批双回退。
- [x] **Milestone 4: 主动例行任务与事件唤醒 (Proactive Automation)**
  - **Cron 周期调度**：内置 5 段式 Cron 匹配器，支持磁盘/健康状态自动巡检与定时简报，支持并发防重叠。
  - **外部 Webhook 接入**：支持监控告警与工单系统事件入站唤醒，提供 Bearer Secret 鉴权、429 并发限流与外部数据隔离保护。
  - **零差异全链路闭环**：主动任务与人工会话共享统一 Runtime，遇到高危操作同样进入 Sentinel 挂起并通过飞书/如流等待管理员确认。
- [ ] **Milestone 5: 通讯录式多角色调度 (Roster UI)**
  - 落地多 Bot 角色面板（数据分析助理、工单巡检助理、代码审查助理）。
  - 双端（Web + 企业 IM）状态同步与审批联动。
- [ ] **Milestone 6: 数据飞轮与自进化**
  - 任务轨迹收集并输出标准训练数据格式，用于私有模型迭代。
  - 探索高频工作流自动提炼为持久化 Skill。
